# ARCHIVE.EXE — owner anomaly cheat-sheet (v0.9.14)

Not intended for public-facing explanation.

- Main logo: automatic glitch roughly every ~14.5s check, often fires; hover can trigger it too. Duration ~1.25s.
- RANDOM: 1% chance to briefly reveal `RECORD_000 / UNKNOWN`; it cannot be opened and vanishes before a normal random bot appears.
- RANDOM: every 13th click still surfaces `RECORD 13 // CLASSIFICATION WITHHELD`.
- Controls / filters / catalog items: ~6.5% hover chance for a very brief red damaged-file `?` state. Click still works.
- Ordinary RGB/signal glitches on interactive elements are rarer (~3.5%).
- Bot cards: ~4.5% hover chance for a short damaged-frame glitch.
- Bot cards: ~1.8% hover chance to briefly overlay `RECORD_000` without changing the bot.
- Catalog: opening it / switching tabs may briefly replace a tab label with `???????` or `[MISSING]`.
- Catalog → Authors: sometimes flashes an impossible `@██████` entry and removes it before it can be used.
- Result count: occasionally displays one extra record for <1 second, then corrects itself.
- Hashtags: rarely change visually to `#unknown`, `#missing`, `#do-not-index`, `#still-here`, or `#record-000`; real filter value never changes.
- Search reactions: `404`, `???`, `lost`, `node_00`, `archive`, `archive.exe`, `record_000`.
- Five rapid clicks on the main logo: `NODE_00 REMEMBERS YOU.`
- Three rapid clicks on the blinking underscore/cursor: temporary `SIGNAL LOCKED / NODE_13`.
- Footer `UNKNOWN FILES: 01`: opens the LOST_DIRECTORY terminal; Recovery Attempt cycles its hidden fragments.

Hidden motif: the archive occasionally behaves as if an unindexed `RECORD_000` exists, despite the visible catalog count.
